# SMTH OS technical audit — November 2026

Scope: full repository inspection at commit `5dbe535` (plus branch history),
before any changes. This is a baseline report: what exists, what is broken, and
what could not be verified here.

## Environment limits (read first)

| Capability | Available here | Consequence |
|---|---|---|
| Rust 1.100 (rustup) | yes | core can be built, tested, linted |
| Python 3.12 + Pillow + numpy | yes | asset generation and all repository checks run |
| Node/npm | yes (unused) | — |
| root / `sudo` | **no** ("no new privileges") | `live-build`, debootstrap, mount: **cannot run** |
| Docker daemon | no | no container escape hatch for live-build |
| `qemu-system-*` | no | **cannot boot an ISO** |
| JDK / Android SDK / emulator | no (no JDK at all) | APK not built here; CI builds and installs it on an emulator |
| Windows / Wine | no | PyInstaller cannot cross-compile; EXE build and run are CI-only |
| `/dev/kvm` | present, not group-accessible | emulator would need CI anyway |

So: every claim below is either (a) verified by a command in this report's
reproduction section, or (b) explicitly marked unverified/blocked.

## What the project actually is

* Debian Trixie `live-build` image (`auto/config`) for amd64 + arm64, 450 MiB gate.
* A Wayland session made of labwc + Waybar + fuzzel + swaylock/swayidle.
* Twelve GTK4/libadwaita "apps" written as single-file Python 3 scripts plus a
  shared dot-drawing library (`usr/local/lib/smth/smthdot.py`).
* A signed `.smx` extension format (`smthctl`, `tools/build_extension.py`).
* Two companion launchers: an Android HOME app (Kotlin) and a Windows Tkinter app.
* One Rust crate (`freezerd`) with no working behaviour.

## Findings

Severity: **S1** broken for users, **S2** broken/at-risk path, **S3** maintainability.

### S1 — Nine desktop helpers were missing from the image

`config/includes.chroot_after_packages/` contained files named
`...-usr-local-bin-smth-clock`, `...-smth-open`, `...-smth-glance`, `...-smth-mode`,
`...-smth-moded`, `...-smth-vm`, `...-smth-term-overlay`, `...-smth-kbd`,
`...-smth-corelink` — flattened hyphenated filenames, not paths. Inside
`usr/local/bin` those commands did not exist, while:

* `etc/skel/.config/labwc/autostart` ran `smth-moded`,
* `rc.xml` / `rc-desktop.xml` bound `W-grave` to `smth-term-overlay`,
* both taskbars called `smth-glance cpu|mem|disk` every few seconds,
* `smth-clock.desktop` and `smth-open.desktop` pointed at missing executables,
* the Files app launched `smth-open` for images/ISOs/binaries,
* Settings launched `smth-mode`.

Nothing failed at build time; the desktop would have shown dead keys and empty
taskbar modules. The v6 pack import workflow (which rewrote the tree from a ZIP on
every push) is the likely origin.

**Fixed**: files restored to `usr/local/bin`, stale duplicate copies removed, and a
new `tools/check_wiring.py` now fails CI when any desktop entry, autostart line,
keybind, taskbar command, hook script or packaged script is unresolved,
syntactically invalid or not executable.

### S1 — The AHIAN easter egg did not implement the specification

The shipped `ahian` printed an ASCII banner, touched a flag file, copied a Waybar
CSS file and signalled the shell. There were no progressive terminal errors, no
dialog storm, no blue screen, no "wants to make your life beautiful" message, no
9 second countdown and no `unahian` command. Documented behaviour and code did
not match.

**Fixed**: the sequence is now generated by a tested Rust planner
(`smth_core::ahian`, 5 tests) and executed by a GTK front end with a headless
fallback. `unahian` shows the angry red screen with the required copy.

### S1 — Documented palette/typography did not match the product brief

The design contract was orange `#FF7A00` + blue `#2F6BFF` with network font
packages (`fonts-inter`, `fonts-jetbrains-mono`). The requested identity is
black/white/grey with red `#701b35`, Doto/DotGothic16 + Space Mono bundled
offline, and a purple/teal AHIAN mode.

**Fixed**: `tools/palette.json` is now the four-colour source
(`A=#701b35`, `B=#f2c6d2`, `AHIAN_A=#7c4dff`, `AHIAN_B=#00c2a8`); all text assets
and generated artwork were recoloured through the existing `tools/recolor.py`
pipeline; the three fonts are vendored with their OFL licences; the palette test
now also enforces the AHIAN pair and the presence of the bundled fonts.

### S1 — The 450 MiB budget was unachievable with the core package set

Measured closure with `tools/estimate_iso.py`: **2233.5 MiB installed**, including
`libwine` 725 MiB, WebKitGTK 124 MiB, Vulkan 79 MiB, KDE Connect/Qt, WayVNC/GTK3.
`wine` is a metapackage, so lists hid the cost. See `docs/architecture/iso-budget.md`.

**Addressed by architecture, not by raising the limit**: everything above moved to
signed extensions; the core closure is now 1050 MiB (est. ~381 MiB ISO). The ISO
build itself remains unverified here.

### S2 — Release workflows published untested or unintended artifacts

* `launchers.yml` had no tag check and published a release on **every push to
  `main`** using a hard-coded `tag_name: launcher-v1.0.0`, silently replacing
  previous assets, and did not verify the EXE at all.
* `build.yml` published on any `v*` tag without confirming both architecture
  artifacts were present or producing checksums.
* `import-smth-v5-pack.yml` referenced a ZIP that does not exist; the v6 variant
  rewrote the working tree from a ZIP with `contents: write` on demand.

**Fixed**: releases are tag-gated and require verified artifacts; APKs are checked
with `unzip -t`, DEX presence, `aapt` package/activity identity, bundled font
presence and `apksigner verify`; the EXE is smoke-tested (process must stay alive);
both import workflows and the pack ZIP were removed, and the reason is recorded
in `docs/architecture/extensions.md`.

### S2 — `freezerd` was a scaffold presented as a daemon

`freezerd/src/main.rs` polls a TODO function that always returns an empty vector,
so it can never freeze anything; no systemd unit exists, yet the chroot hook tried
to enable `freezerd.service`. **Documented, not deleted**; it is no longer enabled
and should be treated as a design sketch until the foreground-state IPC exists.

### S2 — Android launcher had fake UI and dead code

* A `DotBackground` class was defined and never used.
* The dock was four `●` characters in a `TextView` — decorative, not clickable.
* The app list was eight hard-coded package names; on most devices the grid was
  mostly "App not installed" toasts.
* Filtering only set cells to `GONE` inside a `GridLayout`, leaving holes.
* Fixed 4 columns regardless of window size; no landscape handling.

**Fixed**: apps are enumerated from `PackageManager`, the grid is rebuilt on every
filter, columns adapt to screen width, the dock resolves four real installed apps,
long-press opens app info, fonts and the dot field are bundled/drawn, the icon and
theme are SMTH-branded, and pointer icons are suppressed so no mouse cursor
appears. Compilation itself is verified in CI, not here.

### S2 — Windows launcher failed silently

`webbrowser.open("ms-settings:")` cannot open a protocol handler; several targets
had no fallback; failures raised modal dialogs with raw exceptions; the window had
a fixed 4-column grid and no keyboard access.

**Fixed**: scheme handlers use `os.startfile`, each app has fallbacks, failures are
reported in an in-window status line, Escape closes and Ctrl+F focuses search,
columns are computed from width, and the bundled fonts are registered
process-locally.

### S3 — Miscellaneous

* `smth-files` swallowed every `OSError` (`except OSError: pass`) on rename,
  create, copy and paste: silent data-operation failures.
* `notifd.py` never removed expired entries from `self.cards` timers; `close()`
  leaks a GLib source per toast.
* `smth-lock` is `swaylock -f` only; the required PIN/pattern/password choice is
  **not implemented** (see incomplete features).
* `smth-hook` hides upstream launchers by writing into package-owned `.desktop`
  files.
* `docs/architecture/acceptance-tests.md` is a plan with no executed evidence.

Status of these: recorded here; the lock/PIN item is called out as incomplete
rather than faked, and the remaining items are queued as follow-ups.

## Not verified (blocked here, must be run in CI)

* ISO build for either architecture, and booting it.
* Android APK **install and launch**: the APK compiles and passes integrity,
  identity and signature checks here, but this environment has no emulator/KVM
  access and no system image. CI runs it on an API 35 emulator.
* Windows EXE build and smoke test: no Windows host, no Wine, and no `tkinter` in
  this Python build, so neither the PyInstaller build nor a GUI run is possible
  here (CI: windows-latest).
* Any on-screen interaction (windows, split screen, dialogs, AHIAN animation).
* GitHub Actions results and release assets.

## Reproduction

```sh
cd core && cargo test --workspace && cargo clippy --workspace --all-targets -- -D warnings
python3 tools/check_wiring.py && python3 tools/test_palette.py
python3 tools/estimate_iso.py --arch amd64 --check-names
```

# SMTH OS architecture — P0 foundations

## Vision
Windows-style desktop muscle memory on a modular, RAM-first live system, with SMTH's black surfaces and two-colour dot art.

## Palette contract
- Canonical source: `tools/palette.json`.
- A: `#ff7a00`; B: `#2f6bff`.
- Wallpaper and logo pixels: black, A, or B only.
- UI text and glyphs: white; surfaces: black. No intermediate shades, alpha, gradients, blur, or shadows.
- Runtime copies and GTK tokens are generated by `tools/gen_tokens.py`; never hand-edit generated copies.
- Recolour with `python3 tools/recolor.py '#RRGGBB' '#RRGGBB'`.

## Design tokens
- 4 px spacing base; 1 px borders; window/flyout radius 8 px; controls 4 px; pills 999 px.
- Taskbar 48 px; icon 24 px; hit target 40 px (44 px in touch mode).
- Motion: 83/167/250/333 ms, cubic decelerate in and accelerate out. Reduce motion disables all motion.
- Type: Inter UI; JetBrains Mono code. Dot numerals are generated from A/B dot columns.
- Signature pointer: hollow triangle, B outer edge and A inner stroke.

## Architecture decision — provisional
| Base | Advantages | Risks for this product | Decision |
|---|---|---|---|
| Debian Trixie minbase | glibc; broad GTK4, WebKit, PipeWire, NetworkManager, Wine/QEMU package support; amd64 and arm64 | Larger than Alpine/Tiny Core; package selection must be measured | **Default** |
| Alpine | Small base; musl; amd64/arm64 | glibc compatibility and desktop package integration add complexity; Wine/box64 support needs validation | Not selected |
| Tiny Core | Very small bootable base; extension model | GTK4/WebKit/PipeWire/NetworkManager desktop stack would need substantial custom packaging | Inspiration for modularity, not base |
| Buildroot | Highly controllable, tiny appliance images | No general-purpose desktop package ecosystem; app maintenance burden | Not selected |

Debian minbase is a starting decision, not proof of the size or RAM targets. CI must measure the finished image and runtime before marking budgets VERIFIED.

## Planned image layout
- `core.squashfs`: kernel/modules, init, labwc, taskbar/shell essentials, terminal and core utilities.
- Signed `.smx` squashfs extensions: Browser, Hypervisor, Creative, Office-lite, Developer.
- Extension manifest: id, version, compressed size, RAM estimate, dependencies, SHA-256, Ed25519 signature.
- Live modes: Live, persistence, install, safe graphics, recovery shell, copy-to-RAM.
- Existing live-build layout remains in place until extension mounting and signing are implemented and tested.
